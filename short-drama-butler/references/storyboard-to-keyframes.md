# 从导演版分镜到关键帧执行单

`storyboard.md` 是单集画面内容的唯一来源；`keyframe-execution.md` 是它的生产镜像，不可重写故事。v2 的 `keyframe-execution-manifest.json` 是逐帧计划、实际输入、质检和版本历史的唯一机器可读状态源；Markdown 只展示当前确认版。

## 默认帧数

- 5 秒或最后不足 5 秒的余数镜头：`start_only`，只生成首帧。
- 10 秒镜头：`start_end`，生成首帧和尾帧。
- `start_middle_end` 只允许用于 10 秒的中间状态确实不可省略的镜头。必须在 `keyframe-plan.md` 写明 `exception_reason`，并由用户逐镜明确确认；普通确认不会默认保留第三张，未被明确确认即改回两帧。

## 字段映射

| 导演版分镜字段 | 执行单字段 | 用途 |
| --- | --- | --- |
| 镜号、时长、景别、运镜 | 原样保留 | 控制视频镜头时长与镜头语言。 |
| 关键帧画面 / 首帧 A、尾帧 B / 动作过程 | 起点、动作过程、终点 | 决定帧图和图生视频动作；动作过程必须带秒数节拍。 |
| 台词与口型时间段、非说话嘴型控制、角色声线、声音策略、音效 | 原样保留 | 明确口型、画外音闭嘴、配音声线与声音制作。 |
| 入点、出点 / 转场 | 原样保留 | 让剪辑和镜头衔接可执行。 |
| 素材参考、分镜出图提示词 | 原样保留 | 保证视觉素材和静帧出图不漂移。 |
| 无 | `KF<镜号>-start/middle/end.png` 与各帧提示词 | 执行单唯一新增字段。 |

每镜输入必须补齐：景别、运镜、场景、按名称的素材参考、起点、动作过程时间轴、终点、台词、角色声线、声音策略、音效、入点、出点 / 转场、原分镜出图提示词，以及与已确认策略完全对应的帧图提示词。执行单不另造标题；`motion` 取自“动作过程”，配音说明取自“角色声线”。

视频提示词由这些字段合成，不得省略时长、画幅、镜头语言、动作阶段、口型 / 声音策略、衔接和视觉约束。

## v2 素材输入与连续性

每镜仍以 `asset_references` 保留读者可见的素材名称；同时必须有结构化 `asset_uses`。每项应声明：

- `reference`：资产 ID、名称或别名。用户一直使用名称或别名；系统必须解析为唯一稳定资产 ID。
- `role`：仅限背景、人物身份、道具身份、光线、构图或风格六类；连续性锚点、编辑目标和参考板不能由分镜伪造。
- `required`：为真时该项必须进入某个阶段，不能因 5 图限制被静默删除。
- `view_hint` / `facing`：需要时指定已登记的角色或场景视图；无法使用首选视图时，系统记录回退原因。
- `relationship_group` 与连续性标记：用于表达不能拆开的持有、接触或跨镜一致性关系。

每张帧图的 `frame_spec` 还要明确写出 `continuity_contract`。没有承接关系时写 `null`；有承接关系时精确列出前序镜号和帧类型、要继承的维度，以及相关资产 ID。它不从动作、场景或转场文字推断。前序图未成为确认 final revision 时，当前帧保持等待，不允许出图。连续性合同只说明要等哪一帧确认，并不把上一镜变成身份母版：每一帧仍必须回到已确认的角色/场景/道具母版；上一镜只作动作、机位、视线、情绪的辅助参考，不能当唯一或主身份锁，也不能镜头链式传递外观。

## 生成、质检与版本

剧本/分镜确认和关键帧方案确认仍是两道用户关口。之后才可创建 v2 执行单，并为单帧准备阶段计划。计划每阶段最多 5 张输入。角色/场景/道具母版是必传身份锁；已确认的上一镜只占可选连续性槽，不能顶替母版。超过 5 图时先丢掉上一镜辅助，再把 required 母版分到后续阶段。后续阶段的 `edit_target` 只承接**同一帧**上一阶段的产图，不是把镜头 2 的身份锁在镜头 1 上。required 输入装不下时必须分阶段；不可拆关系组仍超限时，先建立、登记并由用户确认同一计划的参考板，再重新规划。

`prepare_keyframe_generation` 只解析输入和持久化计划，不调用或绑定任何图片、视频、剪辑供应商。外部图片调用方必须先用 `butler.py dispatch-keyframe`（或直接调用 `begin_stage_generation`）派发阶段；该函数重新核验输入 SHA-256，冻结计划提示词和输入并返回唯一 `dispatch_id` 与参考图路径。没有参考图路径时禁止调用图片工具。生成返回时，`butler.py record-image` 必须收到同一 `dispatch_id`、提示词和输入，才会保存工作图至 `keyframes/work/KF<镜号>-<帧类型>/rNNN-<阶段>.<扩展名>`。每次阶段生成都必须走 `butler.py record-qa`：自动 QA 只有该阶段所有 required 类别均通过且每项置信度至少 0.85 才能通过；不确定、低置信度或参考板结果交由用户审核。失败或否决只重做该阶段，并保留旧 revision 和理由。已确认帧需要用户主动重做时使用 `butler.py redo-keyframe`；它让旧计划失效并重新阻塞直接依赖该帧的连续性帧。

只有最后阶段 QA 通过，系统才写入 `keyframes/final/KF<镜号>-<帧类型>/rNNN.<扩展名>` 并将它记录为可查询的连续性锚点。新 revision 不覆盖旧文件；确认 revision 通过 manifest 的 `supersedes` / `superseded_by` 保留版本链。v2 不创建新的 `keyframes/pending/`。旧 manifest 无 schema v2 时标记 `legacy_unplanned`，只能查看或人工归档；不得自动生成、迁移、移动或覆盖其 `pending/` 文件或旧执行单。新建 v2 执行单同样拒绝覆盖已有执行单；旧文件必须先人工归档。

## 用户参考图

用户给关键帧提供额外图片时，先询问图片约束的维度和范围，而不是把它当作全部视觉事实。登记时将项目内文件复制到 `references/user/` 并记录 SHA-256。人物身份或道具身份必须绑定唯一目标资产；背景、光线、构图和风格各自只影响声明维度。范围为单镜、明确镜号列表的连续段或整集；单镜优先于连续段，连续段优先于整集，同范围较新项优先，被替代项保持可追溯。用户覆盖不改写素材索引或角色圣经。
