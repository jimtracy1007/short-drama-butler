# 图片生成一致性设计

日期：2026-08-15  
状态：已确认，待实施

## 目标

在 GPT 单次最多接收 5 张参考图的限制下，让短剧关键帧尽可能稳定地保持：

- 人物身份、造型、配色、服装、身体结构和朝向一致。
- 场景空间、机位、建筑、地形、时间和光源方向一致。
- 关键道具的形状、材质、颜色、尺寸、持有人和位置一致。
- 同镜首帧、过程帧、尾帧以及相邻镜头之间的状态连续。
- 用户临时指定的背景、人物、道具、光线或构图参考能够覆盖默认选择，且不会污染其他维度。

系统必须把参考图选择、分阶段生成和质检结果写入机器可读文件。不能只在提示词里写“保持一致”。

## 非目标

- 不调用视频生成或剪辑 API。
- 不承诺图像模型做到像素级确定性。
- 不用增加无关资产或更多关键帧来掩盖一致性问题。
- 不把某个具体图像平台的私有参数写死在项目配置中。
- 不修改已经确认的原始资产图。

## 核心约束

1. 任意一次图片生成或编辑调用最多使用 5 张参考图。
2. 每张参考图必须有实际存在的项目内路径、明确用途和优先级。
3. 持续出现的重要人物、场景和道具必须先登记为资产，才能进入正式关键帧生成。
4. 用户指定的参考图只覆盖用户声明的维度。
5. 复杂镜头允许分阶段生成。每个阶段仍须遵守 5 张上限。
6. 已确认阶段是后续阶段的底图和不变量，失败时只重做出错阶段。

## 方案选择

采用“自适应分阶段生成”，并保留参考板作为极端群像镜头的兜底。

未采用的主方案：

- 固定优先级单次生成：调用少，但多人、多道具镜头会丢失参考对象。
- 始终使用合并参考板：节省槽位，但会降低单个人物和小道具的有效分辨率。

参考板只能用于无法通过合理分阶段处理的群像镜头，不能替代已确认的单体资产图。

## 架构

### 1. 资产引用解析器

复用现有名称和别名解析能力，把分镜中的自然语言名称解析为稳定资产 ID。解析结果必须包含：

- `asset_id`
- `name`
- `kind`：`characters`、`scenes` 或 `props`
- `scope`
- `views`：全部视图及路径

正式生成前，解析器必须拒绝：

- 索引中不存在的持续性人物、场景或关键道具。
- 名称不唯一的资产。
- 图片路径不存在的资产。
- 只有名称、没有任何可用图片的资产。

### 2. 参考图调度器

新增独立的纯逻辑组件，为每一张关键帧生成参考图计划。输入包括：

- 当前镜头和帧类型。
- 景别、机位、人物朝向和画面状态。
- 已解析资产及全部视图。
- 上一镜已确认最终帧。
- 同镜上一张已确认帧。
- 用户参考图覆盖规则。
- 单次最多 5 张参考图的限制。

输出包括：

- `generation_mode`：`single_pass` 或 `staged_edit`
- `reference_images`
- `stages`
- `invariants`
- `continuity_anchor`
- `user_overrides`
- `unresolved_assets`

调度器不调用图片工具，便于单元测试和不同图片工具复用。

### 3. 图片生成执行器

执行器严格按调度器的阶段计划逐次调用图片工具。每个输入图都要标明用途：

- `edit_target`
- `continuity`
- `background`
- `character_identity`
- `prop_identity`
- `lighting`
- `composition`
- `reference_board`

执行器必须记录实际发送的图片路径和角色，不能只记录素材名称。

### 4. 视觉质检器

每个阶段生成后先质检，再进入下一阶段。质检结果写入状态文件，至少覆盖人物、场景、道具和连续性四类问题。

自动质检不能确认的情况进入用户审核，不得静默标记为通过。

## 数据结构

`keyframe-execution-manifest.json` 中的每帧增加生成计划。示例：

```json
{

  "frame_kind": "end",
  "generation_mode": "staged_edit",
  "continuity_anchor": {
    "path": "keyframes/final/KF09-start.png",
    "source": "same_shot_previous_frame"
  },
  "user_overrides": [
    {
      "path": "references/user-beach-background.png",
      "role": "background",
      "scope": "shot"
    }
  ],
  "stages": [
    {
      "stage_id": "background",
      "operation": "generate",
      "reference_images": [
        {
          "path": "references/user-beach-background.png",
          "role": "background",
          "priority": 100,
          "required": true
        }
      ],
      "invariants": [
        "保持用户参考图的海岸线、机位和光线方向"
      ]
    },
    {
      "stage_id": "primary_characters",
      "operation": "edit",
      "reference_images": [
        {
          "path": "keyframes/work/KF09-end-background.png",
          "role": "edit_target",
          "priority": 110,
          "required": true
        },
        {
          "path": "assets/global/characters/C01_gulu/front.png",
          "role": "character_identity",
          "asset_id": "C01",
          "priority": 90,
          "required": true
        }
      ],
      "invariants": [

        "不得改变已确认背景、机位、光线和海岸线"
      ]
    }
  ]
}
```

任一 `reference_images` 数组长度不得超过 5。

## 参考图选择规则

### 视图选择

人物视图按画面朝向选择：

- 正面或四分之三正面：优先 `front`。
- 明确侧身：优先 `side`，缺失时回退 `front` 并记录回退原因。
- 背向镜头：优先 `back`，缺失时不得假装已有背面参考，进入质检警告。
- 表情特写：可使用 `expression-sheet`，但不能替代身体视图。

场景视图按机位选择：

- 正打：`front` 或 `view-a`。
- 反打：`reverse`。
- 侧面或空间关系镜头：`side`、`wide` 或 `top`，由镜头说明决定。
- 没有匹配机位时，使用最接近视图并记录回退原因。

### 单次调用优先级

每个阶段内部按以下优先级分配最多 5 个槽位：

1. 当前阶段编辑底图。
2. 用户明确指定且适用于当前阶段的参考图。
3. 同镜上一张已确认帧或上一镜连续性帧。
4. 当前机位的场景参考图。
5. 当前阶段主要人物参考图。
6. 当前阶段关键道具参考图。
7. 次要人物参考图。
8. 参考板。

优先级只在同一阶段内比较。调度器不能因为人物过多而挤掉编辑底图，也不能因为用户指定背景而删除当前阶段必须使用的人物参考。

## 生成模式

### 单次生成

当所有必需参考图不超过 5 张时使用。典型组成：

- 场景参考图 1 张。
- 连续性锚点 1 张。
- 主要人物 1 至 2 张。
- 关键道具 0 至 1 张。

单次生成后仍须质检。

### 分阶段生成

必需参考图超过 5 张，或镜头包含多个需要分别锁定的维度时使用。

#### 阶段 A：背景

锁定场景、机位、构图、地形、建筑、时间和光线。可使用：

- 用户背景、光线或构图参考。
- 当前机位场景图。
- 上一镜空间连续性帧。

输出无人物或只保留已经确认且不能移除的主体。

#### 阶段 B：主要人物

以阶段 A 输出为 `edit_target`，加入承担主要动作或台词的人物。提示词必须包含：

- 只添加指定人物。
- 不得改变背景、机位、光线和已存在对象。
- 每个人物的位置、比例、朝向和动作。

#### 阶段 C：次要人物和道具

以阶段 B 输出为 `edit_target`，加入剩余人物和关键道具。每个对象必须有明确位置、比例、朝向、持有人或接触关系。

对象仍然过多时，可以拆成多个 C 阶段。每次编辑只处理一组对象。

### 同镜多帧

- 首帧按单次或分阶段模式生成。
- 过程帧必须把已确认首帧作为连续性锚点。
- 尾帧必须把最近的已确认过程帧或首帧作为连续性锚点。
- 后续帧只改变分镜明确要求改变的动作、表情、镜头或物体状态。

### 跨镜承接

下一镜在以下任一条件成立时使用上一镜最终确认帧：

- 同一场景且人物或道具位置连续。
- 入点明确承接上一镜动作、视线或构图。
- 道具在两个镜头之间由同一角色持有。

场景、时间或叙事段落明确切换时，可以解除空间锚点，但人物和道具身份锚点仍保留。

## 用户参考图覆盖

用户可以声明参考图用途：

- 背景
- 人物身份
- 道具身份
- 光线
- 构图
- 整体风格

默认作用域是当前镜头。只有用户明确说“后续都用”“本集都用”或“设为固定参考”时，才扩展到连续镜头或整集。

覆盖规则：

- “参考这张图的背景”只替换背景锚点。
- “人物按这张图”只替换指定人物的身份锚点。
- “参考光线”不能改变场景结构、人物身份或道具形状。
- “参考构图”不能覆盖资产的固定视觉设定。
- 用户未说明用途时，系统只问用途；不能把图片当作全维度参考。

所有覆盖必须写入 `user_overrides`，包括路径、角色、作用域、来源和创建时间。

## 未登记资产关口

下列对象必须先进入资产生产流程：

- 跨两个或更多镜头持续出现的剧情道具。
- 会被角色拿起、传递、放下或特写展示的道具。
- 影响场景构图的固定结构，例如持续出现的沙堡、水道或特殊装置。
- 新人物或需要保持固定形态的生物。
- 需要多个机位保持空间关系的重要场景。

一次性、无叙事意义的环境装饰可不登记，但不能作为后续连续性锚点。

## 状态与文件

每张帧图记录：

- `planned`
- `generating`
- `generated`
- `pending_review`
- `confirmed`
- `needs_regeneration`
- `failed`

状态记录至少包含：

- 当前文件路径。
- 实际使用的参考图和用途。
- 生成阶段。
- 生成时间。
- 质检结论。
- 重做原因。
- 被替代版本的路径，不覆盖旧文件。

工作中间图放在 `keyframes/work/`，确认成图放在 `keyframes/final/`。中间阶段失败时保留最近一张通过质检的底图。

## 视觉质检

### 人物

- 身体轮廓、配色、服装和标志物。
- 发型、角、耳朵、尾巴和肢体数量。
- 当前镜头视图与参考图是否匹配。
- 多人镜头中身份是否串位。

### 场景

- 机位和空间结构。
- 建筑、地形、入口、水体和固定物位置。
- 时间、天气、光源方向和色温。
- 正反打是否来自同一空间。

### 道具

- 形状、材质、颜色和尺寸。
- 持有人、接触关系和画面位置。
- 前一帧与当前帧之间的状态变化是否符合动作。

### 连续性

- 人物站位、朝向和动作状态。
- 道具的出现、消失、传递和放置。
- 场景变化是否由分镜明确要求。
- 同镜多帧之间是否只改变规定内容。

质检失败必须输出具体原因，例如：

- `prop_color_drift: 小贝壳由粉蓝变成黄色`
- `character_feature_missing: 泡泡队长帽子消失`
- `scene_orientation_flip: 水道方向左右反转`

重做时把原因转成当前阶段的不变量或禁止项。

## 错误处理

- 参考图超过 5 张：不得截断；必须重新分阶段。
- 用户指定图片不存在：停止当前镜头，报告准确路径。
- 资产无法解析：停止正式生成，进入资产生产关口。
- 缺少所需视图：允许明确回退，但写入质检警告。
- 阶段生成失败：只重试当前阶段，不重画已经确认的阶段。
- 质检失败：生成新版本，保留旧版本和失败原因。
- 用户否决生成结果：记录用户原因，调整对应阶段，不扩大修改范围。

## 兼容与迁移

- 保留现有 `asset_references` 名称列表，供人阅读。
- 新增解析后的 `asset_ids`、`reference_paths`、`generation_mode` 和 `stages`。
- 旧执行单没有参考图计划时标记为 `legacy_unplanned`，不得直接进入自动生图。
- 已经标记为 `superseded_downstream_files` 的旧关键帧方案仍然不可使用。
- 现有资产索引中的多视图全部保留，交接包和执行单应展示实际选择的视图，而不只是主图。

## 测试策略

### 单元测试

- 1 至 5 张必需参考图生成单次计划。
- 第 6 张必需参考图触发分阶段计划。
- 任一阶段的参考图数量不超过 5。
- 人物正面、侧面、背面和表情视图选择正确。
- 场景正打、反打、侧面和空间图选择正确。
- 用户背景覆盖只替换背景锚点。
- 用户人物覆盖不改变场景参考。
- 同镜过程帧和尾帧使用最近确认帧。
- 跨镜连续场景使用上一镜最终确认帧。
- 场景切换解除空间锚点，但保留人物身份锚点。
- 未登记持续性道具阻止生成。
- 重做阶段保留已确认底图。
- 不存在路径、歧义名称和空视图正确报错。

### 集成测试

以 EP002 为回归案例：

- 小彩纹贝壳必须先登记为道具资产。
- 圆润沙堡必须登记为场景固定结构或道具资产。
- 后段群像自动使用分阶段模式。
- 用户指定海滩背景只覆盖默认场景视图。
- 每个阶段保存实际参考图输入。
- 贝壳、人物和水道在连续镜头中保持可追溯锚点。

### 静态检查

- 执行单不能出现只有名称、没有 `asset_id` 或图片路径的正式参考。
- 每个阶段最多 5 张参考图。
- 每个编辑阶段必须有且只有一个 `edit_target`。
- 用户覆盖必须有明确用途和作用域。

## 验收标准

1. 任何关键帧在生成前都能回答“实际参考了哪几张图、每张图负责什么”。
2. 任意一次图片调用不超过 5 张参考图。
3. 超过 5 个必需参考对象时自动生成分阶段计划，不静默丢弃对象。
4. 用户指定背景、人物、道具、光线或构图参考能准确覆盖对应维度。
5. 同镜后续帧和连续镜头使用已确认帧作为锚点。
6. 未登记的持续性人物、场景和道具不能进入正式生成。
7. 视觉质检能记录具体失败原因，并只重做出错阶段。
8. 旧版本图片和失败版本可追溯，不被覆盖。
9. EP002 的贝壳、沙堡、人物和海滩场景都进入可验证的一致性链路。
